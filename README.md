# COBOL Game Mainframe

A production-oriented launcher and single-domain gateway for:

- [Trump vs. Shakespeare](https://github.com/Pepitodrop/TrumpVsShakespeare)
- [Crazy Mini Golf](https://github.com/Pepitodrop/CrazyMiniGolf)
- [Crazy Race](https://github.com/Pepitodrop/CrazyRaceGame)

The intended public URL is **`https://game.luisbenedikt.de`**.

## COBOL is the main application language

GamePage deliberately uses **COBOL as its application and decision layer**. Go is retained only for work that is substantially safer and more maintainable in a networking-focused runtime: HTTP transport, reverse proxying, WebSocket forwarding, concurrent health probes, process signals, and connection management.

The system does not silently reimplement COBOL decisions in Go. If the COBOL core is unavailable or returns structurally invalid data, GamePage fails closed: readiness becomes degraded and launch links are disabled.

### Responsibilities

| Layer | Language | Responsibilities |
| --- | --- | --- |
| Application core | **COBOL** | Route registry, runtime policy, configuration decisions, health aggregation, maintenance mode, readiness, launchability, reason codes, status JSON, launcher generation, status-client generation, and architecture metadata |
| Transport adapter | Go | HTTP server, reverse proxy, WebSockets, upstream probes, path/header/cookie rewriting, security headers, logging, graceful shutdown, and invocation/validation of the COBOL engine |
| Generated browser artifacts | HTML, CSS, JavaScript, SVG | Launcher presentation and live status UI; generated by compiled COBOL programs |
| Deployment | Dockerfile, YAML, Bash, Apache/Caddy config | Build, orchestration, CI, smoke tests, and TLS termination |

### COBOL programs

| Program | Purpose |
| --- | --- |
| `src/gamepage.cob` | Generates the launcher HTML, CSS, base JavaScript, SVG favicon, 404 page, `robots.txt`, and `security.txt` |
| `src/gamepage_registry.cob` | Generates the authoritative route registry, runtime policy, architecture manifest, and the launchability-aware browser status client |
| `src/gamepage_core.cob` | Runtime decision engine that validates input records, aggregates service health, applies maintenance policy, calculates readiness and launchability, assigns reason codes, and emits the complete status JSON document |

The generated runtime files are:

```text
/app/site/runtime/routes.tsv
/app/site/runtime/policy.tsv
/app/site/runtime/architecture.json
```

Go loads these COBOL-generated files instead of maintaining a second hard-coded game registry.

## Runtime decision flow

```text
Browser / monitoring
        |
        v
Go HTTP transport
        |
        | concurrently performs technical HTTP probes
        v
raw per-game observations
        |
        | secure temporary input in /tmp
        v
GnuCOBOL gamepage-core
        |
        | validates records and applies application policy
        v
COBOL-generated status JSON
        |
        | Go validates structure, then transports it unchanged
        v
/api/status or /readyz
```

COBOL decides:

- whether configuration input is valid;
- whether maintenance mode is active;
- whether the complete stack is ready;
- whether each game may be launched;
- the aggregate state: `ok`, `degraded`, `maintenance`, or `configuration-error`;
- the reason associated with every launchability decision;
- the summary counts and JSON response structure.

Go only supplies observations such as HTTP status and latency.

## Status endpoints

| URL | Purpose |
| --- | --- |
| `/healthz` | Go transport-process liveness; does not claim application readiness |
| `/readyz` | Forces fresh probes and a COBOL decision; returns 200 only when COBOL reports `ready: true` |
| `/api/status` | Cached COBOL decision document used by the launcher and monitoring |

Example response shape:

```json
{
  "overall": "ok",
  "ready": true,
  "mode": "normal",
  "decisionEngine": "gnucobol",
  "checkedAt": "2026-07-14T10:00:00Z",
  "summary": {"total": 3, "up": 3, "down": 0},
  "games": {
    "trump": {
      "name": "Trump vs. Shakespeare",
      "path": "/play/trump/",
      "status": "up",
      "httpStatus": 200,
      "latencyMs": 12,
      "launchable": true,
      "reason": "ready"
    }
  }
}
```

The Go adapter verifies the COBOL engine identity, timestamp, overall-state vocabulary, route identities, and result completeness before returning the document.

## Maintenance mode

Set:

```env
MAINTENANCE_MODE=true
```

Accepted true values are `1`, `true`, `yes`, and `on`, case-insensitively. Accepted false values are `0`, `false`, `no`, `off`, or an empty value. COBOL validates this value.

During maintenance mode:

- `/healthz` remains available;
- `/api/status` reports `overall: maintenance` and `mode: maintenance`;
- `/readyz` returns HTTP 503;
- all game records have `launchable: false` and `reason: maintenance`;
- the COBOL-generated status client removes game-link destinations and displays `MAINTENANCE`.

Restore `MAINTENANCE_MODE=false` and recreate the GamePage container to leave maintenance mode.

## Reverse-proxy behavior

The games were designed to run at the root of an origin. The Go transport adapter therefore performs protocol-level tasks that do not belong in the COBOL business layer:

1. strips `/play/...` before forwarding upstream;
2. restores the prefix in root-relative textual URLs;
3. rewrites `Location` headers;
4. rewrites cookie `Path` attributes;
5. preserves WebSocket upgrades;
6. forwards origin and prefix headers;
7. disables upstream compression before bounded response rewriting.

A text response larger than 16 MiB is rejected rather than rewritten without bounds.

## Docker image

The GamePage image has three stages:

1. **COBOL builder**
   - compiles all three COBOL programs;
   - generates browser assets, registry, policy, and architecture metadata;
   - builds the runtime `gamepage-core` executable;
   - validates required generated outputs.
2. **Go builder**
   - runs Go tests;
   - builds the static transport binary.
3. **Runtime**
   - contains the Go transport, the compiled COBOL application core, generated site files, `libcob`, and CA certificates;
   - contains neither the COBOL compiler nor the Go toolchain;
   - runs as numeric non-root user `65532:65532`.

The Compose service uses a read-only root filesystem. A bounded, `noexec` `/tmp` tmpfs is provided solely for short-lived COBOL input/output files and is cleaned after every decision.

## Configure and start

```bash
cd /srv/games/GamePage
cp .env.example .env
chmod 600 .env
docker compose config --quiet
docker compose build --pull
docker compose up -d --wait --wait-timeout 240 --remove-orphans
bash scripts/docker-smoke-test.sh
```

For local HTTP testing, temporarily set:

```env
PUBLIC_ORIGIN=http://127.0.0.1:8090
```

Restore the production HTTPS origin before public deployment.

## Continuous integration

### Core CI

`.github/workflows/ci.yml` verifies:

1. `go test -race ./...` and `go vet ./...`;
2. compilation of all COBOL programs;
3. generated launcher, registry, policy, architecture, and status-client files;
4. healthy, degraded, and maintenance decisions produced by the real GnuCOBOL engine;
5. JSON parsing and expected readiness/launchability behavior;
6. Docker Compose model validity;
7. the production GamePage image build.

### Full-stack Docker CI

`.github/workflows/full-stack-docker.yml` checks out all four repositories, builds every image, starts the complete stack, waits for health, and verifies:

- launcher availability;
- all three routed games;
- `overall: ok`;
- `decisionEngine: gnucobol`;
- at least one positive `launchable` decision;
- canonical redirects;
- absence of published game ports;
- clean shutdown and removal.

The workflow is triggered by COBOL, Go, Docker, Compose, environment, and smoke-test changes, and also runs weekly to detect sibling-repository drift.

## Security model

- only the gateway port is published, bound to `127.0.0.1`;
- games run on an `internal: true` Docker network;
- the gateway has fixed upstreams and cannot act as an open proxy;
- COBOL input is generated from validated, delimiter-safe fields;
- the COBOL result is structurally validated before transport;
- a missing or malformed COBOL result fails closed;
- temporary decision files use mode `0600` inside a bounded tmpfs and are removed immediately;
- services use read-only filesystems, resource limits, log rotation, capability drops where supported, and `no-new-privileges`;
- TLS terminates at Apache or Caddy;
- `security.txt` points to GitHub private vulnerability reporting.

## Public deployment

Create DNS `A` record `game` pointing to the server. Add `AAAA` only after IPv6 routing and proxying are verified.

The host reverse proxy must forward HTTP and WebSocket traffic to `127.0.0.1:8090` and set:

```apache
RequestHeader set X-Forwarded-Proto "https"
```

Deployment examples are in `deploy/`. After TLS is active, verify:

```bash
curl --fail https://game.luisbenedikt.de/healthz
curl --fail https://game.luisbenedikt.de/readyz
curl -sS https://game.luisbenedikt.de/api/status | python3 -m json.tool
```

Finally create a Trump vs. Shakespeare online room and confirm that a second public client reaches `Live`; this is the required external WebSocket test.

## Updating and rollback

Before updating, record all four repository SHAs. Then:

```bash
git pull --ff-only
git -C ../TrumpVsShakespeare pull --ff-only
git -C ../CrazyMiniGolf pull --ff-only
git -C ../CrazyRaceGame pull --ff-only
docker compose build --pull
docker compose up -d --wait --wait-timeout 240 --remove-orphans
bash scripts/docker-smoke-test.sh
```

To roll back, check out the recorded commits in each repository, rebuild, restart, and rerun the smoke test. Active rooms are in memory and do not survive container replacement.

## Troubleshooting

### `/readyz` returns 503

Inspect the COBOL result first:

```bash
curl -sS http://127.0.0.1:8090/readyz | python3 -m json.tool
docker compose logs --tail=200 gamepage
docker compose ps
```

- `overall: degraded` means at least one probe was down.
- `overall: maintenance` means COBOL accepted an enabled maintenance value.
- `overall: configuration-error` means COBOL rejected the decision input.
- `decisionEngine: unavailable` means the Go adapter could not execute or validate COBOL and failed closed.

### Verify COBOL ownership

```bash
curl -sS http://127.0.0.1:8090/api/status \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d["decisionEngine"], d["overall"])'
```

Expected normal output begins with `gnucobol ok`.

## Known limits

- The stack targets one server and hobby or small-community traffic.
- The runtime starts one short-lived COBOL process per uncached status decision; this is intentional and bounded, but not designed for high-frequency telemetry workloads.
- Horizontal replicas require shared room storage and coordination in the duel and race games.
- Active online rooms are not preserved across restarts.
- Final public verification still requires real DNS, TLS, and an external WebSocket room test.
