# COBOL Game Mainframe

A production-oriented landing page and single-domain gateway for three independent browser games:

- [Trump vs. Shakespeare](https://github.com/Pepitodrop/TrumpVsShakespeare)
- [Crazy Mini Golf](https://github.com/Pepitodrop/CrazyMiniGolf)
- [Crazy Race](https://github.com/Pepitodrop/CrazyRaceGame)

The public target is **`https://game.luisbenedikt.de`**. The launcher is generated from real GnuCOBOL source. The three game repositories remain completely unchanged and are built from sibling folders by this repository's Docker Compose stack.

## What this repository provides

- A responsive game-selection page generated by compiled **GnuCOBOL**.
- One public hostname with stable paths for all games.
- A small standard-library **Go** gateway for HTTP reverse proxying, WebSocket forwarding, health checks, and path-safe response rewriting.
- A hardened Docker Compose topology in which only the gateway is exposed to the host.
- Apache and Caddy reverse-proxy examples for HTTPS.
- Live status indicators for every game.
- CI checks for Go, COBOL, Docker, and the Compose model.
- A production runbook covering DNS, TLS, deployment, updates, rollback, troubleshooting, and security.

## Public URL map

| Public URL | Service | Internal target |
| --- | --- | --- |
| `/` | COBOL-generated launcher | GamePage gateway |
| `/play/trump/` | Trump vs. Shakespeare | `http://trump-vs-shakespeare:8000/` |
| `/play/golf/` | Crazy Mini Golf | `http://crazy-mini-golf:8080/` |
| `/play/race/` | Crazy Race | `http://crazy-race:8080/` |
| `/api/status` | Aggregated game status | GamePage gateway |
| `/healthz` | Gateway liveness | GamePage gateway |
| `/readyz` | Gateway plus all game readiness | GamePage gateway |

The three game containers have no host port mappings. They are reachable only from the private `games` Docker network.

## Why a gateway is necessary

The games were designed to run at the root of their own origin. Some of them use absolute URLs such as `/create`, `/api/rooms`, `/ws/...`, or `/assets/...`. A basic reverse proxy mounted at `/play/race/` would therefore send the browser back to the wrong root path.

The GamePage gateway solves this without modifying any game repository:

1. It removes the public mount prefix before forwarding a request upstream.
2. It rewrites root-relative URLs in textual HTML, CSS, JavaScript, JSON, manifests, and SVG responses.
3. It rewrites upstream `Location` response headers.
4. It rewrites cookie `Path` attributes.
5. It preserves WebSocket upgrades and rewrites the Trump vs. Shakespeare WebSocket URL.
6. It disables upstream compression before transformation and allows the outer HTTPS proxy to compress the final response.

Example flow:

```text
Browser POST /play/race/create
             |
             v
GamePage gateway strips /play/race
             |
             v
Crazy Race receives POST /create
             |
             v
Upstream Location: /room/ABC123
             |
             v
Browser receives Location: /play/race/room/ABC123
```

## Architecture

```text
Internet
   |
   | HTTPS :443
   v
Apache or Caddy on the host
   |
   | HTTP/WebSocket over loopback
   v
127.0.0.1:8090
GamePage Go gateway
   |                  |                    |
   | private network  | private network    | private network
   v                  v                    v
Trump vs.          Crazy Mini           Crazy Race
Shakespeare        Golf                 :8080
:8000              :8080

Launcher assets:
src/gamepage.cob -> GnuCOBOL compiler -> generated HTML/CSS/JS/SVG/text
```

## Language responsibilities

The goal is to use COBOL wherever it remains practical while keeping the deployment secure and maintainable.

| Layer | Language/tool | Responsibility |
| --- | --- | --- |
| Launcher UI source | **COBOL** | Generates the HTML, CSS, status client, 404 page, favicon, `robots.txt`, and `security.txt` |
| Launcher build | **GnuCOBOL** | Compiles and executes the asset generator during the container build |
| Gateway | **Go standard library** | HTTP server, reverse proxy, WebSockets, URL rewriting, redirects, cookie rewriting, health aggregation, graceful shutdown |
| Orchestration | Docker Compose | Builds sibling repositories and isolates services |
| Public TLS | Apache or Caddy | HTTPS certificates and internet-facing reverse proxy |
| Games | Their existing languages | Remain unchanged in their own repositories |

### Why the gateway is not written entirely in COBOL

A production WebSocket-aware reverse proxy requires careful handling of HTTP upgrades, streaming, cancellation, timeouts, headers, connection pooling, and graceful shutdown. Implementing that directly in COBOL would require substantial C socket interop and would be harder to audit than Go's mature standard-library proxy implementation. COBOL therefore owns the complete visible launcher artifact, while Go is deliberately restricted to infrastructure work.

## Required server directory layout

Clone all four repositories next to one another. The default paths in `.env.example` assume this exact structure:

```text
/srv/games/
├── GamePage/
├── TrumpVsShakespeare/
├── CrazyMiniGolf/
└── CrazyRaceGame/
```

Only `GamePage` is changed by this project. Docker uses the sibling folders as read-only build contexts.

## Prerequisites

- A Linux server with Docker Engine and Docker Compose v2.
- Git.
- A reverse proxy on the host: Apache 2.4.47 or newer, or Caddy.
- Public TCP ports 80 and 443 available for the reverse proxy.
- DNS control for `luisbenedikt.de`.
- Enough build resources for Rust, Node.js, Python/native Assembly, R, Go, and GnuCOBOL images. A machine with at least 4 GB RAM is recommended for reliable concurrent builds; lower-memory servers should build services sequentially.

No COBOL, Go, Rust, Node.js, Python, or R installation is required on the host because all builds occur in containers.

## First deployment

### 1. Clone the repositories

```bash
sudo mkdir -p /srv/games
sudo chown "$USER":"$USER" /srv/games
cd /srv/games

git clone https://github.com/Pepitodrop/GamePage.git
git clone https://github.com/Pepitodrop/TrumpVsShakespeare.git
git clone https://github.com/Pepitodrop/CrazyMiniGolf.git
git clone https://github.com/Pepitodrop/CrazyRaceGame.git
```

### 2. Create the environment file

```bash
cd /srv/games/GamePage
cp .env.example .env
chmod 600 .env
```

The defaults already target `https://game.luisbenedikt.de` and the sibling repository layout. Review the settings before continuing:

```bash
sed -n '1,200p' .env
```

### 3. Build the full stack

```bash
docker compose build --pull
```

On a server with limited RAM, build one service at a time:

```bash
docker compose build gamepage
docker compose build trump-vs-shakespeare
docker compose build crazy-mini-golf
docker compose build crazy-race
```

### 4. Start the stack

```bash
docker compose up -d --remove-orphans
```

### 5. Verify container health

```bash
docker compose ps
docker compose logs --tail=100 gamepage
curl --fail http://127.0.0.1:8090/healthz
curl --fail http://127.0.0.1:8090/readyz
```

Expected behavior:

- `/healthz` returns HTTP 200 when the gateway process is alive.
- `/readyz` returns HTTP 200 only when all three games respond to their health endpoints.
- `/readyz` returns HTTP 503 with a JSON status document if any game is down.

## DNS setup

Create the following DNS record at the provider managing `luisbenedikt.de`:

| Type | Name | Value |
| --- | --- | --- |
| `A` | `game` | The server's public IPv4 address |

Add an `AAAA` record only when the server has working public IPv6, the firewall permits IPv6 traffic, and Apache/Caddy listens on IPv6. A broken `AAAA` record can make the website unreachable for IPv6-capable clients.

Use a short TTL, such as 300 seconds, during initial setup. Confirm resolution before requesting a certificate:

```bash
getent ahosts game.luisbenedikt.de
```

## Apache deployment on Ubuntu

This is the recommended path when the server already uses Apache.

### 1. Enable required modules

```bash
sudo a2enmod proxy proxy_http proxy_wstunnel rewrite headers ssl
```

### 2. Install the bootstrap vhost

```bash
sudo cp deploy/apache-bootstrap.conf \
  /etc/apache2/sites-available/game.luisbenedikt.de.conf
sudo a2ensite game.luisbenedikt.de.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
```

The bootstrap vhost proxies HTTP to `127.0.0.1:8090` and explicitly preserves WebSocket upgrades.

### 3. Verify HTTP before requesting TLS

```bash
curl --fail http://game.luisbenedikt.de/healthz
```

### 4. Request and install the certificate

With Certbot and its Apache integration installed:

```bash
sudo certbot --apache -d game.luisbenedikt.de --redirect
```

Choose the redirect option so all HTTP traffic is sent to HTTPS. Certbot creates or updates the `:443` vhost and manages certificate renewal.

After Certbot creates the HTTPS vhost, verify that its proxy section sets:

```apache
RequestHeader set X-Forwarded-Proto "https"
```

The reference file `deploy/apache-https.conf.example` contains the expected final directives.

### 5. Verify HTTPS and WebSockets

```bash
curl --fail https://game.luisbenedikt.de/healthz
curl --fail https://game.luisbenedikt.de/readyz
curl -I https://game.luisbenedikt.de/
```

Then open Trump vs. Shakespeare, create an online room, and confirm that its status changes to `Live`. This validates both WebSocket proxy layers.

The file `deploy/apache-https.conf.example` shows the expected final HTTPS structure. Do not overwrite Certbot-managed certificate paths unnecessarily.

## Caddy alternative

Caddy can obtain and renew TLS automatically. Make sure no other process is using ports 80 or 443, then use `deploy/Caddyfile`:

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy forwards ordinary HTTP and WebSocket upgrades to the loopback gateway automatically.

## Updating the deployment

Pull every repository explicitly so an update is deliberate and reviewable:

```bash
cd /srv/games/GamePage
git pull --ff-only

git -C ../TrumpVsShakespeare pull --ff-only
git -C ../CrazyMiniGolf pull --ff-only
git -C ../CrazyRaceGame pull --ff-only
```

Rebuild and replace containers:

```bash
docker compose build --pull
docker compose up -d --remove-orphans
curl --fail http://127.0.0.1:8090/readyz
```

Important: Trump vs. Shakespeare and Crazy Race keep active rooms in process memory. Recreating those containers ends active rooms. Perform updates during a quiet period.

## Rollback

Before an update, record the current commit of every repository:

```bash
for repo in GamePage TrumpVsShakespeare CrazyMiniGolf CrazyRaceGame; do
  printf '%-24s ' "$repo"
  git -C "/srv/games/$repo" rev-parse HEAD
done
```

To roll back, check out the recorded commits and rebuild:

```bash
git -C /srv/games/GamePage checkout <GAMEPAGE_COMMIT>
git -C /srv/games/TrumpVsShakespeare checkout <TVS_COMMIT>
git -C /srv/games/CrazyMiniGolf checkout <GOLF_COMMIT>
git -C /srv/games/CrazyRaceGame checkout <RACE_COMMIT>

cd /srv/games/GamePage
docker compose build
docker compose up -d --remove-orphans
```

Return each repository to its branch after the incident is resolved.

## Security model

- Only `127.0.0.1:8090` is published by Docker.
- The game containers are connected only to an internal Docker network.
- Game services are not reachable directly from the internet or the host network.
- Containers use read-only root filesystems where supported.
- Linux capabilities are dropped for the non-root gateway, duel, and race services. Mini Golf retains the capability set expected by its stock Nginx image while still using a read-only filesystem and `no-new-privileges`.
- `no-new-privileges` is enabled.
- CPU, memory, PID, and log limits are defined.
- The gateway validates every configured upstream URL.
- The gateway has fixed routes and cannot be used as an open proxy.
- Textual response rewriting is capped at 16 MiB.
- Security headers are added by the gateway, and upstream game headers are retained.
- Trump vs. Shakespeare accepts only the configured public origin.
- TLS termination occurs only at Apache or Caddy.
- A `security.txt` file points researchers to GitHub private vulnerability reporting.

`FORWARDED_ALLOW_IPS=*` is used only inside the private Docker network for Trump vs. Shakespeare. The service has no published host port, so forwarded headers can arrive only through containers attached to this stack's internal network.

## Data and backups

GamePage itself has no database and creates no persistent volume.

- Crazy Mini Golf stores scores in browser Local Storage.
- Trump vs. Shakespeare rooms are in memory and disappear on restart.
- Crazy Race rooms are in memory and disappear on restart.
- Crazy Race track generation is reproducible when `TRACK_SEED` is positive.

Back up the repository checkouts, `.env`, and host reverse-proxy configuration. There is no server-side game save data to back up.

Recommended backup targets:

```text
/srv/games/GamePage/.env
/srv/games/*/.git
/etc/apache2/sites-available/game.luisbenedikt.de.conf
/etc/letsencrypt/
```

Protect `.env` and Let's Encrypt private keys with restrictive permissions.

## Continuous integration

The GitHub Actions workflow performs these gates:

1. `go test -race ./...`
2. `go vet ./...`
3. GnuCOBOL installation and compilation.
4. Execution of the COBOL generator.
5. Assertions that all generated launcher assets and game links exist.
6. Docker Compose model validation.
7. A complete GamePage container build.

The workflow does not clone or modify the three game repositories. Their own repositories remain responsible for their internal tests. The complete server deployment builds their current checked-out commits through the sibling build contexts.

## Troubleshooting

### `/readyz` returns 503

Inspect the JSON response to identify the failed game, then check that container:

```bash
curl -sS http://127.0.0.1:8090/readyz | python3 -m json.tool
docker compose ps
docker compose logs --tail=200 <service-name>
```

### Docker cannot find a build context

The sibling folder name or `.env` path is wrong. Verify:

```bash
ls -la ..
grep '_REPO_PATH' .env
docker compose config | grep -A3 'context:'
```

### Mini Golf or Race build fails from low memory

Build services sequentially rather than together. Also inspect free memory and disk space:

```bash
free -h
df -h
docker system df
```

### Trump vs. Shakespeare creates rooms but never becomes `Live`

This normally indicates a WebSocket proxy problem.

1. Confirm Apache modules are enabled.
2. Confirm the WebSocket rewrite rules exist in the active HTTPS vhost.
3. Check browser developer tools for the `/play/trump/ws/...` request.
4. Check Apache and GamePage logs.
5. Verify `PUBLIC_ORIGIN=https://game.luisbenedikt.de`.

```bash
sudo apache2ctl -M | grep -E 'proxy|rewrite|headers'
sudo apache2ctl -S
docker compose logs --tail=200 gamepage
```

### A game redirects to `/` instead of its mounted path

The gateway normally rewrites both response bodies and `Location` headers. Confirm the request actually passed through GamePage and was not sent directly to a game container. No game container should publish a host port.

```bash
docker compose config | sed -n '/trump-vs-shakespeare:/,/^[^ ]/p'
docker compose config | sed -n '/crazy-mini-golf:/,/^[^ ]/p'
docker compose config | sed -n '/crazy-race:/,/^[^ ]/p'
```

### HTTPS works for some clients but not others

Check for an incorrect IPv6 `AAAA` record. Remove it until IPv6 is fully configured.

```bash
getent ahosts game.luisbenedikt.de
curl -4I https://game.luisbenedikt.de/
curl -6I https://game.luisbenedikt.de/
```

### Apache reports port 8090 unavailable

Another service is using the configured loopback port. Find it or change `GAMEPAGE_PORT` in `.env` and update the Apache/Caddy target to match.

```bash
sudo ss -ltnp | grep ':8090'
```

## Known limits

- The gateway's path transformation intentionally targets text-based web content. A future upstream game change that embeds root URLs inside a binary format may require an additional rewrite rule.
- Active online rooms are not preserved across container replacement.
- The stack is designed for a single server and modest hobby or small-community traffic.
- Horizontal replicas require shared room storage for Trump vs. Shakespeare and Crazy Race before scaling.
- The launcher health badges are informational and do not prevent users from opening a temporarily unavailable game.
- HSTS should be enabled only after HTTPS is confirmed working correctly.
